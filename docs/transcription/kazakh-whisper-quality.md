# Качество казахского распознавания на Deepgram Whisper

Открытая проблема, зафиксирована 2026-08-03, не разобрана. Отдельна от фикса
про таймаут (тот убирал ложную ошибку «запись слишком длинная») — здесь речь о
качестве самого распознавания.

Живёт в репозитории, а не в заметках, потому что напрямую влияет на решение о
замене провайдера для казахского, которое уже стоит в планах.

## Симптом

Запрос с `language=kk` на казахскую речь:

- распознанное **переведено на русский**, а не записано по-казахски;
- **много слов пропущено**.

## Сырой JSON-ответ

> **Ещё не приложен.** Симптом описан словами, сам ответ не сохранялся. Без
> тела ответа нельзя отличить перевод на уровне модели от подмены языка в
> запросе — это первое, что нужно для разбора.

```json
(вставить ответ Deepgram целиком)
```

## Что известно про запрос, который его породил

Точная строка параметров, которую сейчас формирует
`backend/src/modules/consultations/infrastructure/deepgram-whisper.ts`:

```
model=whisper-medium&smart_format=true&diarize=true&punctuate=true&language=kk
```

## Рабочие гипотезы

1. **Whisper переводит, а не транскрибирует.** У OpenAI Whisper есть две
   задачи — `transcribe` и `translate`, и вторая всегда переводит на
   английский. Перевод именно на русский под это не подходит, но проверить
   наличие управляющего параметра у Deepgram стоит первым делом.
2. **`language=kk` не долетает или игнорируется**, и модель сама выбирает
   доминирующий язык — а на казахской речи с русскими терминами это может
   оказаться русский.
3. **`diarize=true` на Whisper.** В матрице возможностей Deepgram диаризация
   для Whisper отмечена как поддерживаемая, но это самая молодая часть
   интеграции, и она меняет форму ответа.
4. **Пропуск слов — свойство `whisper-medium`.** Есть `whisper-large`, он
   медленнее (а латентность и так проблемная, см. ниже), но точнее.

## Связанный замер латентности (из фикса про таймаут)

На файле в **3 секунды тишины**, один и тот же ключ, с интервалом в минуты:

| Запрос | Время |
|---|---|
| `whisper-medium` + полный набор для `multi` | таймаут >180 с |
| `whisper-medium` + `language=kk` + полный набор | 45,6 с |
| `whisper-medium` + `detect_language` без остального | 80,4 с |
| `whisper-medium` + `detect_language` + `diarize` | 0,9 с |
| `whisper-medium` без параметров языка | 1,0 с |
| `whisper-medium` + `language=kk` без остального | 5,9 с |
| `nova-2` + `language=ru` (контроль) | 1,8 с |

Разброс от 1 до 180+ секунд на одном и том же входе. Deepgram сам пишет, что
Whisper «менее масштабируем, чем все остальные модели».

## Вывод для решения о провайдере

Качество (перевод вместо транскрипции, пропуск слов) и латентность бьют в одну
точку: **Deepgram Whisper выглядит непригодным для казахского в проде**. Это
довод перенести замену провайдера для `kk`/`multi` на ISSAI или свой сервер
раньше, чем планировалось. Роутер
(`infrastructure/transcription-router.ts`) для этого и сделан — замена стоит
одного адаптера и строки в таблице.

## Что нужно, чтобы разобрать

3. Прогон того же аудио через `whisper-large` и через `detect_language` для
